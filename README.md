# Модуль общения — сайт-ядро

Экран с крупными плитками для человека без речи: нажал плитку — прозвучало слово.
Пользователь не читает, смысл несёт картинка. Чистые HTML/CSS/JS (ES-модули),
без сборщика и npm-зависимостей — сайт запускается прямо из папки репозитория.

Это **Задача 1 (ядро)**: показать плитки, озвучить, открыть папку.
Редактор, пароль, генерация озвучки и программа для Windows — в следующих задачах.

## Структура

```
index.html
styles.css
js/app.js          экран и навигация
js/parser.js       разбор content.md (чистый модуль без DOM, работает и в Node)
js/sound.js        озвучка
content/content.md данные
tests/parser.test.mjs
README.md
```

## Как открыть локально

Нужен локальный веб-сервер: страница читает `content/content.md` через `fetch`,
а по протоколу `file://` браузер этот запрос блокирует.

```bash
python -m http.server
```

Затем откройте в браузере: <http://localhost:8000>

## Как опубликовать на GitHub Pages

1. Загрузите содержимое этой папки в репозиторий на GitHub.
2. В репозитории: **Settings → Pages**.
3. **Build and deployment → Source: Deploy from a branch**.
4. Branch: **main**, папка **root (/)** → **Save**.
5. Через минуту сайт будет по адресу
   `https://<ваш-логин>.github.io/<имя-репозитория>/`.

Все пути в проекте относительные, поэтому подпапка репозитория работает без правок.

## Самопроверка

```bash
node tests/parser.test.mjs
```

Тест проверяет: на главном экране 17 плиток в нужном порядке, у «Мультики» 3
ребёнка, у «Болит» 8; и на трёх коротких неверных текстах — ошибки с верным
номером строки (нет раздела «Плитки», строка без «- ключ: значение», пропуск
уровня заголовка).

## Принятые решения

То, что в ТЗ не было описано явно, — выбран самый простой вариант:

- **Порядок реакций на клик.** Сначала подсветка рамки (`#1d4ed8`) и увеличение
  на 300 мс, затем — по истечении этих 300 мс — озвучка и переход (в папку /
  открытие ссылки / запуск автовозврата). Трактует «…рамка на 300 мс…; затем
  озвучка» буквально.
- **Значения настроек и свойств.** `да`/`нет` → `true`/`false`; строки, целиком
  состоящие из числа (например `0.8`, `8`) → число; остальное (например `6x3`,
  `#2b6cb0`) → строка.
- **Цвет рамки по умолчанию** `#cbd5e1` проставляется уже в парсере, поэтому
  `tile.border` всегда заполнен.
- **Номер строки для «нет раздела „Плитки“»** — `1` (ошибка на весь файл,
  указываем на начало).
- **Кнопка «Назад»** всегда занимает одно и то же место: на главном экране
  скрывается через `visibility: hidden`, а не `display: none`, чтобы сетка не
  «прыгала».
- **Автовозврат** срабатывает только внутри папки и только для плитки без детей;
  `0` (или нечисло) выключает; любой новый клик сбрасывает таймер. Возврат идёт
  сразу на главный экран.
- **Авто-id** (`t1`, `t2`, …) выдаются плиткам без `id` по порядку появления и
  не пересекаются с уже занятыми явными id.
- **Картинка, которой нет на диске** (в Задаче 1 картинок ещё нет): плитка
  показывается как цветной блок с подписью.
- **Озвучка без файла.** Сначала пробуется `звук`, затем `content/audio/<id>.mp3`;
  пока этих файлов нет, запрос вернёт 404 и включится речь браузера
  (`speechSynthesis`, `ru-RU`). Это ожидаемо до Задачи 3.
- **Громкость по умолчанию** — `1`, если ключ `громкость` не задан; значение
  ограничивается диапазоном `0.0–1.0`.
- **Сетка** берётся из `сетка` (`столбцов×строк`, разделитель `x` или `×`);
  область плиток не прокручивается, как и требуется.

## Демо-набор картинок и озвучки (добавлен по запросу пользователя)

Исходное ТЗ Задачи 1 поставляло `content.md` без картинок и без аудиофайлов
(плитки рисовались цветными блоками, озвучка шла только речью браузера).
После приёмки Задачи 1 в данные добавлен демо-набор — код при этом не менялся:

- `content/img/<id>.png` — комплект из 28 AI-пиктограмм в едином AAC-стиле
  (плоский рисунок, толстый контур, белый фон, без текста); в `content.md`
  у каждой плитки ключ `- картинка: img/<id>.png`;
- прежний линейный SVG-комплект сохранён в резерве вне проекта:
  `../svg_reserve/` (генератор `../tools_gen/svg_gen.py` больше не используется);
- `content/audio/<id>.mp3` — озвучка названий (мужской голос, ru); звук плитки
  берётся оттуда автоматически, по правилу ТЗ `content/audio/<id>.mp3`.
  Озвучка выкладывалась партиями (лимит синтеза — 10 файлов за ход):
  теперь готовы все 28 плиток (28 уникальных mp3) одним и тем же одобренным
  голосом (мужской, ru). Резервная речь браузера остаётся только как fallback
  на случай отсутствия файла.
